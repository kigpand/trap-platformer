# 렌더링 지침
- 렌더링은 시뮬레이션 상태를 변경하면 안 됩니다.
- CanvasRenderingContext2D를 통한 그리기와 게임플레이 갱신을 분리합니다.
- 브라우저 픽셀 비율과 카메라 변환을 명시적으로 정규화합니다.
- 애니메이션 프레임 안에서 에셋을 불러오지 않으며, 소유한 자원을 정리합니다.
- 바닥으로 위장한 함정, 가짜 체크포인트·가짜 클리어 깃발·가짜 벽처럼 처음엔 구분되면 안 되는 것은 진짜와 같은 그리기 함수(`terrain.ts`의 `drawGround`·`drawBlock`, `props.ts`)와 같은 애니메이션 프레임으로 그립니다. 같은 자리에서 진짜와 픽셀 단위로 같은지 `terrain.test.ts`·`props.test.ts`로 확인합니다.
- 지형 무늬는 월드 좌표로만 정하고 테두리를 넣지 않습니다(잘라 그린 바닥에 이음매가 생기면 위장이 깨집니다). 움직이는 것은 움직인 만큼 무늬를 함께 옮깁니다.
- 그림에 `Math.random`을 쓰지 않습니다. 무늬는 칸 번호의 고정 해시, 애니메이션은 렌더링 전용 시간(`performance.now`)으로 정해 테스트에서 재현되게 합니다.
- 길이 방향으로 늘어나는 것(지형, 배경 건물, 무늬)은 화면에 걸치는 부분만 그립니다.
- 화면 흔들림·파편은 렌더러만 가진 그림 상태이며 `World`를 바꾸지 않습니다. 배경처럼 화면 전체를 덮는 그림은 흔들림 폭만큼 화면 밖으로 더 그립니다.
- 판정이 있는 것(가시 등)은 판정 사각형 밖으로 그리지 않습니다.
- 새 색은 테스트가 구분에 쓰는 색(`SPIKE_FILL`, 경고색, `GOAL_FILL` 등)과 겹치지 않게 고릅니다.
- 그린 결과는 `tests/unit/rendering/recorder.ts`(fillRect를 1px 격자로 펼침)로 비교하고, 그림을 바꾼 뒤에는 개발 서버 화면을 확대 캡처해 눈으로도 확인합니다.
