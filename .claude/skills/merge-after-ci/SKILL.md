# CI 확인 후 병합
프로젝트 오너가 이번 대화에서 이 PR의 병합을 명시적으로 요청했을 때만 사용합니다. 다른 PR이나 이후 PR로 승인을 넓히지 않습니다.

1. CI 확인: `gh pr checks <번호> --watch`로 기다린 뒤, 통과한 실행이 PR의 **최신 커밋**(`gh pr view <번호> --json headRefOid`) 기준인지 확인합니다. 실패하면 병합하지 않고 실패 내용을 보고합니다.
2. 병합: `gh pr merge <번호> --merge`. 병합 커밋을 기록합니다.
3. 로컬 동기화: `master`로 전환해 `git pull --ff-only`. 커밋하지 않은 로컬 변경은 건드리지 않습니다.
4. 배포 확인: `deploy.yml` 실행을 기다려 결과와 대상 커밋을 확인하고, 배포된 사이트(https://kigpand.github.io/trap-platformer/)에서 이번 변경이 실제로 반영됐는지(예: 번들에 새 코드·색 문자열, 새 파일 응답 200) 확인합니다.
5. 개발 일지: AGENTS.md "개발 일지" 규칙대로 Notion에서 병합 날짜의 행을 먼저 찾아 갱신하고, 없으면 새로 만듭니다. 커밋과 변경으로 확인되는 사실만 씁니다. 쓰지 못했으면 성공처럼 보고하지 않습니다.
6. 보고: 병합 커밋, 배포 결과, 확인한 내용, 일지 갱신, 확인하지 못한 것을 짧게 알립니다.
