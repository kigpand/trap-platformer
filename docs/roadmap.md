## 다음 릴리스 — 새 맵 추가
1~4주 차 로드맵 항목은 모두 끝났지만, **MVP 완료 기준은 아직 하나가 남아 있습니다.** 함정의 "학습 가능" 규칙을 확정하면서(`docs/traps-spec.md` "공통 규칙"), 가짜 안전지대의 사망 후 표시가 필요해졌습니다. 이것이 구현될 때까지 `docs/game-design.md`의 "학습 가능한 서로 다른 함정 최소 5종"은 충족되지 않은 상태이며, 아래 1번이 그 항목입니다.

다음 릴리스는 이 MVP 요건을 먼저 채운 뒤 레벨을 여러 개로 늘리는 것을 목표로 하며, 아래 순서로 진행합니다. 각 항목은 별도 PR로 만들고, 완료 기준을 모두 만족해야 체크합니다.

1. [ ] **가짜 안전지대 사망 후 표시** (MVP 요건) — `docs/traps-spec.md` #4의 텔레그래프 규칙 구현.
   - 완료 기준: 가짜 안전지대로 사망하면 재시작 직후 2초간 해당 타일이 강조 표시되고, 다른 원인의 사망·수동 재시작(R)에서는 표시되지 않는다.
   - 테스트:
     - `World` 단위 테스트 — 표시 상태의 시작·2초 후 해제·R로 해제·다른 사망 원인은 표시 안 함.
     - `CanvasRenderer` 단위 테스트 — 그리기 호출을 기록하는 가짜 2D 컨텍스트로, 표시 상태일 때 해당 타일 영역에 강조 색이 그려지고 표시가 끝나면 일반 바닥과 같게 그려지는지 확인(`World` 상태만으로는 실제 화면 표시를 검증할 수 없다).
     - 개발 서버에서 실제 사망 후 강조 표시 화면 확인(스크린샷을 PR에 첨부).
2. [ ] **레벨 데이터 구조 개편** — `level.ts`의 전역 상수를 레벨 객체(지형·함정·적·체크포인트·스폰·목표)로 묶고, `World`가 레벨을 인자로 받게 한다. 동작 변화 없는 리팩터링.
   - 완료 기준: 기존 레벨이 새 구조로 옮겨지고 기존 단위·E2E 테스트가 수정 없이(또는 레벨을 넘기는 부분만 바꿔) 통과한다.
   - 테스트: 기존 테스트 전체, 특히 텔레포트 없는 스폰→목표 자동 플레이 테스트.
3. [ ] **새 레벨 1개 추가** — 함정 5종 중 최소 3종과 적을 레벨 1과 다른 조합으로 배치. `docs/physics-spec.md`의 "레벨 배치 제약"을 지킨다. 진행 흐름(4번) 전이라 게임 화면에서는 아직 선택할 수 없고, 2번의 구조 덕분에 `World`에 직접 넘겨 테스트한다.
   - 완료 기준: 새 레벨 객체로 만든 `World`에서 텔레포트 없는 스폰→목표 자동 플레이 테스트가 통과하고, 각 함정이 학습 가능 요건을 만족한다.
   - 테스트: 새 레벨의 도달 가능성 자동 플레이 테스트, 함정별 트리거 테스트.
4. [ ] **레벨 진행 흐름** — 클리어 후 다음 레벨로 넘어가기, 현재 레벨 표시(HUD), 최고 기록을 레벨별로 저장. 3번의 새 레벨을 실제로 플레이할 수 있게 연결한다.
   - 완료 기준: 레벨 1 클리어 → 레벨 2 시작, 마지막 레벨 클리어 시 완료 화면, 기존 저장 기록(`trap-runner:best`)은 레벨 1 기록으로 이어진다.
   - 테스트: 진행 흐름 단위 테스트, 레벨별 기록 저장 테스트, 다음 레벨 전환 E2E.
   - 착수 전 결정: 레벨 선택 화면 유무, 다음 레벨로 자동 진행할지 버튼으로 진행할지.
