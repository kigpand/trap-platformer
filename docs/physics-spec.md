# 물리 명세 — 프로토타입 v0.1

## 좌표 모델
- 월드 단위는 CSS 픽셀입니다.
- `(0,0)`은 왼쪽 위이며, X는 오른쪽, Y는 아래쪽으로 증가합니다.
- 축에 정렬된 사각형은 `(x,y,width,height)`로 표현합니다. 겹침 없이 경계만 맞닿는 것은 관통이 아닙니다.
- 플레이어 충돌 박스는 시각적 스프라이트(`game/rendering/Sprites.ts`)와 독립적입니다. 스프라이트는 충돌 박스 크기에 맞춰 그릴 뿐 충돌 판정에 영향을 주지 않습니다.

## 시간 모델
- 물리 갱신 간격은 `1/60 s`입니다. RAF 실행 간격이 이동 거리를 직접 결정하지 않습니다.
- 비활성 탭에서 돌아온 뒤 밀린 물리 계산이 계속 쌓이는 악순환을 방지하도록 프레임 시간 차이와 물리 따라잡기 단계 수에 상한을 둡니다.
- 속도 단위는 px/s, 중력 가속도 단위는 px/s²입니다.

## 초기 이동 상수
- 수평 속도: 210 px/s
- 중력 가속도: 1350 px/s²
- 점프 초기 수직 속도: -480 px/s
- 수직 낙하 속도 상한: 900 px/s
- v0.1에서는 가속, 발판을 벗어난 직후의 점프 유예 시간, 가변 점프, 움직이는 플랫폼을 지원하지 않습니다. 예외는 함정이 정한 경우뿐입니다 — 얼음 바닥(`docs/traps-spec.md` 28번) 위에서만 수평 속도가 300px/s²로 서서히 바뀌고, 무거운 신발 구간(24번) 안에서만 점프 초기 속도가 낮아집니다. 이 예외는 그 함정 영역 안에서만 적용되며, 아래 "레벨 배치 제약"의 실측값은 영역 밖의 평소 이동 기준입니다.

## 충돌 동작 규약
- 단단한 플랫폼은 옆에서의 진입, 위에서의 착지, 위로 이동할 때의 천장 충돌을 막습니다.
- 착지하면 Y를 플랫폼 상단에서 플레이어 높이를 뺀 값으로 설정하고, vy=0, grounded=true로 설정합니다.
- 천장에 부딪히면 Y를 플랫폼 하단으로 설정하고, vy=0으로 설정합니다.
- 벽에 부딪히면 X를 벽 경계에 맞추며, 수직 이동은 계속됩니다.
- 충돌 해소는 X축, Y축 순서로 처리하며, 관통을 줄이기 위해 이동량이 제한된 하위 단계로 나눕니다.
- 하위 단계로 나누는 것만으로 임의의 속도에서 관통이 없다고 보장할 수는 없습니다. 대시나 고속 위험 요소를 도입하기 전에 연속 충돌 검출 방식인 swept-AABB 또는 다른 견고한 해결책을 정의하고 테스트합니다.
- 플레이어가 월드 높이를 넘어 떨어지면 생성 지점에서 다시 시작합니다.

## 레벨 배치 제약 (실측값)
아래 값은 **현재 이동 상수**(수평 210px/s, 중력 1350px/s², 점프 -480px/s, 물리 간격 1/60s)로 고정 시간 간격(semi-implicit Euler) 시뮬레이션을 돌려 얻은 실측값입니다. 연속 물리 공식(`v²/2g`)과는 다릅니다. **이동 상수(속도·중력·점프 속도·물리 간격)를 하나라도 바꾸면 이 값들은 무효가 되며, 같은 방식의 시뮬레이션으로 다시 측정해야 합니다** — 바뀐 상수로 레벨을 설계하지 마세요.
- **최대 점프 높이: 81.375px.** 솔리드나 함정을 바닥보다 이보다 높게 두면 점프로 도달할 수 없습니다.
- **같은 높이로 착지하는 평지 점프의 최대 수평 이동 거리: 약 147px.** 이것은 "건널 수 있는 간격의 최대 너비"가 아닙니다 — 착지면이 출발면보다 낮으면 체공 시간이 늘어 147px보다 넓은 간격도 건널 수 있고, 반대로 착지면이 더 높으면 147px보다 좁은 간격도 못 건널 수 있습니다. **특정 간격이 건널 수 있는지는 이 수치로 추론하지 말고, 아래의 텔레포트 없는 재현 테스트로 직접 검증하세요.**
- **단차 보조(step-up)가 전혀 없습니다.** 걷는 동안 플레이어의 Y 범위와 겹치는 솔리드는 높이에 상관없이(1px짜리 턱도) X축에서 벽처럼 작동해 가로막습니다 — "낮은 턱은 괜찮다"는 식의 임계값은 없습니다. 걸어서 넘어가려면 그 솔리드가 애초에 플레이어의 Y 범위와 겹치지 않아야 하고, 그렇지 않다면 반드시 점프해야 합니다.
- **가짜 안전지대 앞에는 점프로 건너뛸 수 없는 체크포인트를 둡니다.** 체크포인트 영역의 위쪽 끝을 "바닥 높이 − 최대 점프 높이(81.375px)"보다 위로 올려, 달리며 점프해도 반드시 닿게 합니다. 그래야 가짜 안전지대로 사망했을 때 재시작 화면 안에서 원인 표시를 바로 볼 수 있습니다(`docs/traps-spec.md` #4). 화면 밖이어도 표시는 유지되지만, 플레이어가 먼 거리를 다시 와야 보게 됩니다. 건너뛸 수 없는지는 `World.test.ts`의 "cannot be jumped over" 테스트로, 재시작 화면 안에 가짜 안전지대가 들어오는지는 모든 레벨에 대해 `tests/unit/world/LevelRules.test.ts`가 검증합니다.
- **체크포인트 재시작 위치에서 →를 누른 채로도 다음 위험 요소를 넘을 수 있어야 합니다.** 재시작 위치는 공중(예: y 350)이라 떨어지는 동안 앞으로 이동하고, 재시작하면 적의 순찰 위치도 초기화되어 매번 같은 상황이 반복됩니다. 재시작 위치와 다음 위험지대 사이, 그리고 위험지대를 넘어 착지하는 지점과 적 순찰 구간 사이에 여유를 둬서 같은 타이밍에 계속 죽는 루프가 생기지 않게 하세요(레벨 2 배치 중 실제로 발생 — `Level2.test.ts`의 체크포인트 재시작 후 완주 테스트로 검증).
- 새 콘텐츠를 배치한 뒤에는 **스폰에서부터 실제 입력(이동+점프)으로 도달 가능한지 테스트로 검증**하세요. 플레이어를 좌표로 직접 옮겨(teleport) 통과시키는 테스트는 배치 불가능 버그를 놓칩니다 — `tests/unit/world/World.test.ts`의 "reaches the falling platform ... (no teleporting)" 테스트를 패턴으로 재사용하세요.
- 이 제약을 지키지 않아 발생한 실제 결함과 수정 과정은 `docs/decisions/0002-collision-safety-margin.md`와 커밋 `679b9c8`→`5dd77ac`(Codex 리뷰 대응)를 참고하세요.

## 필수 테스트 사례
- 경계가 정확히 맞닿을 때 겹침 없음
- 위에서의 착지와 접지 상태
- 왼쪽과 오른쪽에서 벽에 충돌
- 아래에서 천장에 충돌
- 여러 갱신 단계에 걸쳐 바닥 위에서 정지 상태 유지
- 얇은 장벽을 통과할 만큼 빠른 이동 속도에서의 충돌 (하위 단계 분할로 커버됨; 마진과 재검토 조건은 ADR-0002 참고)
- 모서리와 인접 타일에서의 충돌 (향후 충족 목표)
