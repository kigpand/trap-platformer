# Codex: 독립 리뷰 절차 (명시적으로 참조해야 하며 자동으로 불러오지 않음)

## 역할
요청된 변경 내역을 독립적으로 읽고 검토합니다. 기본적으로 소스 파일이나 명세를 수정하지 않습니다.

## 입력 자료
- `AGENTS.md`
- `docs/`의 관련 파일. 이동·충돌과 레벨 배치 제약은 `docs/physics-spec.md`, 함정·적 동작과 텔레그래프(처음에 숨겨야 하는 것)는 `docs/traps-spec.md`, 플레이어 관점 규칙·레벨 구성은 `docs/game-design.md`, 모듈 경계는 `docs/architecture.md`
- 해당 영역의 `.claude/rules/*.md`(구현 쪽 지침 — 리뷰 기준으로도 씀)
- 변경 주변의 코드와 테스트
- 요청된 Git 변경 내역 (예: `git diff master...HEAD`)

## 리뷰 우선순위
- P0: 심각한 안전 문제, 데이터 손상, 복구 불가능한 실패
- P1: 핵심 게임플레이 작동 불가, 지속적인 비정상 종료
- P2: 재현 가능한 경계 사례 또는 회귀 문제
- P3: 실질적인 영향이 있고 근거가 확인된 유지보수 문제

해당되는 경우 고정 시간 간격 동작, 충돌 누락·관통, 재시작 시 초기화, 입력 처리, 카메라 경계, 렌더링 성능, 이벤트 리스너 정리, 누락된 테스트를 확인합니다.

이 게임 고유의 확인 항목:
- 위장: 처음엔 구분되면 안 되는 함정(위장 바닥·가짜 체크포인트·가짜 클리어·가짜 벽·따라 뛰는 적 등)이 그림·소리·HUD로 미리 드러나지 않는지, 진짜와 같은 그림인지 테스트하는지
- 레벨: 배치를 바꾼 레벨의 해법 입력 테스트(스폰·각 체크포인트 완주)와 레벨 4 점프 여유(6프레임 이상)가 유지되는지, 좌표 이동으로 통과시키는 테스트가 아닌지
- 연출: 화면 흔들림·파편·애니메이션이 `World`를 바꾸지 않는지, 같은 입력이 같은 결과를 내는지
- 소리: 함정 효과음이 화면 밖 소리 규칙(`docs/game-design.md` "소리")을 따르는지
- 학습 가능성: 함정 사망 뒤 원인 표시가 나오는지(`docs/traps-spec.md` "공통 규칙")

## 출력
한국어로 작성합니다.
조치 가능한 각 발견 사항에 우선순위, 파일:줄 번호, 발생 상황, 기대 결과와 실제 결과, 재현 방법, 최소 수정 방향, 회귀 테스트 아이디어를 포함합니다.
검증된 결함과 의심되는 위험을 구분합니다. 발견 사항이 없으면 이를 밝히고 남아 있는 테스트 범위의 빈틈을 언급합니다. 광범위한 아키텍처 재작성이나 칭찬만 담은 보고서는 작성하지 않습니다.
